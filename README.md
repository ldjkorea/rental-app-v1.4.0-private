# 임대관리 앱 v1.4.0 — 감사 통합·검증 완료본

이전 작업의 저장·정산·체납 개선을 그대로 이어받고, 미완료 운영 회귀 검증과 실제 오류 수정을 마친 로컬 버전입니다. 원격 운영 사이트에는 배포하지 않았습니다.

## 1. 실행 및 데이터 가져오기

- Windows에서 `실행.cmd`를 더블클릭합니다. Node.js 20 이상이 필요합니다.
- 실행기는 Node.js로 서버를 확인하고 Edge 앱 창을 엽니다. PowerShell 실행 정책을 변경하거나 우회하지 않습니다.
- 기본 주소는 `http://127.0.0.1:4173/`입니다. 다른 폴더의 앱이 같은 포트를 사용 중이면 안내 후 중단합니다.
- 같은 폴더·버전의 서버가 실행 중이면 재사용합니다. 서버는 127.0.0.1에만 연결됩니다.
- 개발 서버만 실행하려면 `npm start`를 사용합니다. `RENTAL_PORT`로 포트를 지정할 수 있습니다.
- 포트를 바꾸면 브라우저 저장소도 분리됩니다. 계속 사용할 주소와 포트를 고정하세요.
- 예시 모드는 주소 끝에 `?demo=1`을 붙입니다. 예시 자료는 `rentalDemo.` 저장 공간으로 분리됩니다.
- 루트 `index.html`은 CSS·JavaScript·아이콘이 포함된 단일 실행본입니다. 이 파일만 복사해서 직접 열 수 있습니다. 안전한 저장에 필요한 Web Locks와 localStorage를 제공하는 브라우저를 사용해야 하며, 지원하지 않는 환경에서 저장 보호를 우회하지 않습니다.
- 개발 소스를 수정하면 `npm run build`로 단일 실행본을 다시 생성합니다. `npm start`, `실행.cmd`, `npm run test:all`도 자동 생성합니다. HTML 편집은 `src/index.template.html`에서 합니다.
- PC는 좌측 사이드바, 800px 이하 화면은 하단 메뉴·모바일 헤더·터치 입력으로 전환합니다. 데이터와 업무 로직은 같습니다.
- 생성 구조와 직접 파일 실행의 제한은 [단일 HTML 사용 및 개발 안내](docs/SINGLE_FILE.md)를 확인하세요.

기존 앱의 설정에서 JSON 백업을 내보낸 뒤, 이 앱의 **설정 → 백업 / 복원 → 파일 가져오기**로 가져옵니다. 가져온 세입자 수·고지서 개월 수와 실제 월별 금액을 대조하세요. 소스 코드에는 실제 운영 데이터가 들어 있지 않습니다.

PWA 새 버전 안내가 표시되면 작업을 저장하고 이 앱의 모든 창을 닫은 뒤 다시 엽니다. 새로고침만으로 기다리는 새 서비스 워커가 적용된다고 가정하지 않습니다.

## 2. 보존한 운영 기준과 데이터 처리

- 월세 납기는 세입자별 `payday`, 관리비·공과금 납기는 해당 월 말일입니다. 납기 다음 날부터 체납으로 집계합니다.
- 누적 체납은 저장된 고지서 기준입니다. 미래 월과 납기 미설정 월세를 임의로 체납에 넣지 않습니다.
- 전기 2·3층은 각각 공급가 35,000원과 VAT 3,500원, 4층은 잔여 공급가와 VAT입니다.
- 수도는 층별 1명 기준이며, 엘리베이터·오물비는 원 단위 실비 합계를 보존합니다. 기존 배분·확정 규칙을 유지했습니다.
- 월세 완납과 관리비·공과금 완납을 구분합니다. 금액·미부과 변경 시 해당 납부확인만 다시 확인하도록 처리합니다.
- 과거 고지서의 금액·호수·계약·납기 정보를 보존합니다. 원본에 없던 값을 현재 정보로 보완한 경우 확인 필요 표시를 남깁니다.
- 고지서가 있는 세입자는 보관 처리하며 과거 고지서와 체납을 유지합니다.
- 저장 키 `rentalApp.state.v1`과 JSON schemaVersion 1 호환을 유지합니다. 다른 앱의 저장값은 지우지 않습니다.
- 저장 실패 시 직전 저장값을 유지하고, 실패한 입력은 백업 내보내기로 복구할 수 있습니다.

## 3. 이번 수정 사항

1. 고지서 진입 직후 지연 갱신이 수정 화면·입력을 지우는 오류를 제거했습니다.
2. 초기화·가져오기 전 복원 지점에 초안을 함께 보관하고 다시 복구합니다.
3. 초안 저장 공간이 부족하면 현재 창에서 초안을 유지하고 내보내기 안내를 지속 표시합니다. 이 상태에서 창을 닫기 전에 백업을 내보내야 합니다.
4. 세입자 정보가 없는 과거 고지서도 저장된 snapshot을 사용해 완납 처리합니다.
5. 저장 실패 시 납부 날짜와 세금계산서 체크를 실제 저장 상태로 되돌립니다. 금액 초안은 유지합니다.
6. Windows 실행기의 폴더 식별값과 서버를 일치시켰고 Node 실행 경로로 통일했습니다.
7. PWA 업데이트 안내를 모든 탭에서 표시하고, 전체 입금일을 읽을 수 있도록 입력칸을 보완했습니다.

## 4. 검증과 재실행

| 검사 | 최종 결과 |
|---|---:|
| JavaScript 문법 검사 | 통과 |
| 계산·납부·저장·캐시·로컬 서버·Windows 실행기 | 55 / 55 통과, 건너뜀 0 |
| 기존 Edge 회귀 시나리오 | 20 / 20 통과 |
| 예시 모드 통합 흐름 | 통과 — 10개 확인 항목 |
| 추가 운영 회귀 시나리오 | 17 / 17 통과 |
| 실제 서비스 워커 설치·업데이트·오프라인 | 5 / 5 통과 |

전체 검사는 다음 한 명령으로 실행합니다.

```text
npm run test:all
```

브라우저 검증에는 기존 Playwright 설치와 Edge가 필요합니다. 공유 Playwright를 사용하는 경우 `NODE_PATH`를 해당 `node_modules` 폴더로 지정하고, Edge 위치가 다르면 `RENTAL_BROWSER`를 지정합니다. 앱 실행 자체에는 외부 런타임 라이브러리가 필요하지 않습니다.

검증기는 해당 작업본을 임시 포트에서 실행하고 별도 브라우저 프로필을 만듭니다. Google 요청은 모의 응답으로 대체하고 외부 요청은 차단합니다. `test-results/`에 결과 JSON·원본 로그·화면 캡처를 남깁니다. 자세한 범위는 [검증 기록](docs/VALIDATION.md)을 확인하세요.

## 5. Google 동기화 및 남은 확인 범위

**현재 Google Apps Script 원본은 이 저장소에 없습니다.** 실제 서버의 인증·원자적 버전 비교·영구 저장을 검증한 상태가 아닙니다.

- 기존 서버의 불러오기는 유지합니다.
- 서버가 조건부 저장과 revision을 지원하지 않으면 업로드를 차단합니다.
- 버전 충돌이나 requestId 확인 실패 시 성공으로 표시하지 않습니다.
- 파일 복원·초기화 후에는 자동으로 덮어쓰지 않으며 서버 자료 대조와 수동 저장이 필요합니다.
- 실제 운영 데이터 이관·운영 서버 통신·GitHub Pages 배포·휴대폰 설치형 앱·물리 프린터는 별도 확인이 필요합니다.

[후속 과제](docs/ROADMAP.md)와 [클라이언트가 요구하는 동기화 규격](docs/GOOGLE_SYNC_CONTRACT.md)을 참조하세요.
