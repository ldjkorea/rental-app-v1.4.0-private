# 건물 운영현황 2차 개발 기록

## 변경 범위

- 기존 메뉴에 `건물 운영현황`을 추가하고 1층부터 5층까지 고정 순서로 표시합니다.
- 임차인이 있는 층은 현재 tenant의 임대상태·계약·월차임을 사용합니다.
- 자동 수납상태와 총 미납금액은 기존 `RentalBilling.collectionStatus()` 결과를 그대로 사용합니다.
- 계약만료 안내만 기존 계약종료일을 기준으로 화면에서 계산하며 저장하지 않습니다.
- 전체·진행중·대기중·연체 필터는 화면 표시만 바꾸고 저장·동기화·audit를 호출하지 않습니다.

## 5층과 호환성

임차인이 없는 층에 허위 tenant를 만들지 않습니다. 같은 `rentalApp.state.v1` 데이터에 선택적인 `floorOperations` 객체를 추가했고 현재 5층의 기본 상태는 `공실(정리중)`입니다. 구형 JSON에 이 필드가 없으면 메모리에서 기본값을 적용하며, 화면을 여는 동작만으로 저장하지 않습니다. 향후 5층 tenant가 생기면 tenant 상태가 우선하므로 기존 임차인 구조와 자연스럽게 연결됩니다.

## 검증 경계

테스트는 샘플·fixture·독립 브라우저 저장소·Google API mock만 사용했습니다. 운영 DB, 운영 Docs, Apps Script 배포와 Sites 배포는 변경하지 않았습니다. 단위 검사 74개와 브라우저 회귀 전체가 통과했으며 HTTP와 단일 HTML 각각 360×800부터 1920×1080까지 확인했습니다.
